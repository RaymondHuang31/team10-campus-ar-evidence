| Week 4 Research Plan v1 - three questions, one per assumption |  |  |  |  |  |  |  |  |
| Scope rule applied: 1-3 assumptions, one verifiable question each. The assumptions chosen are the three that most affect project direction - A1/A2 (problem and its cause), A3 (AR versus phone map) and A7 (buyer and budget). A4/A5/A6 are handled by the supporting feasibility audit below, not by a research question. This is a plan: no RQ has been run yet. |  |  |  |  |  |  |  |  |
| RQ | Assumption tested | Research question | Method | Instrument & measures | Target participants | Recruitment channel | Decision it informs | Evidence ID (planned) |
| RQ1 | A3 | On one unfamiliar indoor-outdoor route, do in-view AR cues reduce map re-checking, wrong turns and perceived workload compared with a phone map? | Within-subject A/B wayfinding task, order counterbalanced, think-aloud plus post-task ratings. | Protocol T1-T6; measures: total time, map re-checks / look-aways, wrong turns or hesitations over ~5s. Ratings R1-R4: workload, confidence, clarity, preference plus reason. | 6-8 unfamiliar users who have not walked the chosen route. | See W4_Recruitment_Plan.xlsx - via first-year tutors and campus reception, never friends. Screening S1/S2 required. | Keeps or kills the AR differentiator: if there is no measurable difference, A3 is not supported and the concept must be re-scoped. | To be assigned after fieldwork (no pre-allocation) |
| RQ2 | A1, A2 | How often, and at which points, do unfamiliar users stop, re-check a map or ask someone during a real campus journey - and is the cause missing information or the difficulty of turning information into movement? | Walk-and-talk semi-structured interview, behaviour-focused, past tense, conducted where the difficulty happened. | G1-G5 in the required order: warm-up, current behaviour, pain, consequence, existing alternatives. No product or price questions. | 6 unfamiliar users: 3 new students (first semester) + 3 first-time visitors. | See W4_Recruitment_Plan.xlsx - first-year tutor for students, reception / visitor services for visitors. | Confirms, narrows or falsifies the problem statement and the A2 revision before any build work. | To be assigned after fieldwork (no pre-allocation) |
| RQ3 | A7 | Who owns the decision and the budget for campus wayfinding support, and under what conditions would they fund or pilot an AR guidance tool? | Structured interview with staff; willingness-to-pay and cost questions asked last, in neutral non-selling wording. | G6-G11 in the required order, ending with: who owns the budget, what a pilot would need, what they compare the cost against, what would make them say no. | 3-4 staff: student experience / campus services, estates or facilities, reception or visitor-services supervisor. | See W4_Recruitment_Plan.xlsx - supervisor or mentor introduction first, then institution email. | Tests whether a buyer exists at all (A7) and what trigger would make a pilot happen. | To be assigned after fieldwork (no pre-allocation) |
| Supporting feasibility audit (not a research question) |  |  |  |  |  |  |  |  |
| - Route audit of 2-3 indoor-outdoor transitions using checklist C1-C8 plus G12-G13: signage, positioning and Wi-Fi coverage, lighting, stairs and lifts, crowding, accessibility, landmark visibility, device rules, and Rokid hardware/SDK confirmation with the mentor. Purpose: choose the RQ1 route deliberately and record the A4/A5 limits. Findings are logged as evidence, not presented as a validated claim. |  |  |  |  |  |  |  |  |
| Order of work and falsification rules (agree before fieldwork) |  |  |  |  |  |  |  |  |
| - Order: pilot the instrument on 1 person -> run the route audit and pick the RQ1 route -> RQ2 walk-and-talk -> RQ1 A/B route task -> RQ3 staff interviews. |  |  |  |  |  |  |  |  |
| - If the first 6 participants say existing maps and signage are already sufficient and show no delay or re-checking, A1/A2 are weakened and the problem must be narrowed or dropped. |  |  |  |  |  |  |  |  |
| - If the A/B route task shows no difference in map re-checks, wrong turns or workload, A3 is not supported and the AR differentiator must be dropped or re-scoped. |  |  |  |  |  |  |  |  |
| - If no staff member can name a budget owner or a pilot route, A7 fails and the customer model must be reconsidered before Week 5. |  |  |  |  |  |  |  |  |
| - If no audited route allows usable tracking and safe device use, there is no deployable pilot route. |  |  |  |  |  |  |  |  |
| - A single pilot is an instrument check only: it is never evidence that in-view AR cues help users navigate. |  |  |  |  |  |  |  |  |
